## 1. 背景（なぜやるか）

ライブラリはあるが、クリップを増やす手段がまだない（ダミーデータのみ）。
本フェーズで「撮る」「取り込む」の2つの入り口を作り、実データが流れる状態にする。

**取り込みがv1必須である理由:** ゴルフスイングやスノーボードのキッカーは動作が非常に速く、
Flutterの `camera` プラグインは高fps（120fps以上のスローモーション）撮影に対応していない。
そのため「端末標準のカメラアプリでスロー撮影 → 本アプリに取り込む」という逃げ道が必須になる。
**アプリ内撮影だけでは商品として成立しない。**

## 2. 具体的な作業内容

### 2.1 依存パッケージ（追加の許可リスト）

既存（`flutter_riverpod` / `go_router` / `path_provider` / `uuid` / `intl`）に加えて、
以下**のみ**を追加してよい。

| パッケージ | 用途 |
|---|---|
| `camera` | アプリ内撮影 |
| `image_picker` | 端末の動画の取り込み |

**禁止（フェーズ1から継続）:**

- `ffmpeg_kit_flutter` 系（2025年に開発終了・バイナリ配布停止済み。絶対に入れない）
- `build_runner` / `freezed` / `json_serializable` などのコード生成系（`toJson`/`fromJson` は手書き）
- Riverpod以外の状態管理の混在
- アナリティクス・広告・クラッシュレポートのSDK（本アプリは通信を一切行わない）
- **`permission_handler`** … `camera` プラグインが権限要求を行うため不要。
  どうしても必要と判断した場合は、理由を添えて**確認を取ること**。
- `video_player` … 本フェーズでは不要。動画の再生・尺取得の目的で入れないこと（理由は2.5）

### 2.2 撮影画面（`/capture`）

- カメラプレビューを全画面表示
- **`CameraController(enableAudio: false)` を必ず指定する。**
  フォーム比較に音声は不要であり、これにより `RECORD_AUDIO` 権限が丸ごと不要になる。
  要求する権限が減ることはストア審査・ユーザーの信頼の両面で有利。**音声を有効にしないこと。**
- 解像度は `ResolutionPreset.high` 程度を既定とする
- **fpsを制御しようとしないこと。** `camera` プラグインはfps指定に対応していない。
  ネイティブを直接叩くなどの回避策も**本フェーズでは試みない**（スロー撮影は取り込みで担保する）
- **画面は縦向き固定でよい**（横撮影対応は未決事項。フェーズ5で判断する）

### 2.3 グリッドオーバーレイ

- **`CustomPaint` で描画する**（画像アセットを使わない）
- 種類: `なし` / `格子3×3` / `格子4×4` / `十字` / `三分割`
- ワンタップで切り替えられること
- **選択したグリッド種類は永続化し、次回起動時も同じ状態で開く**
  → 画角の再現性がこのアプリの価値の根幹。毎回選び直させない
- 線は撮影対象が透けて見える程度の視認性にする（半透明の白＋細い線など）。
  **録画される映像にグリッドを焼き込まないこと。** あくまで画面上のガイド

### 2.4 カウントダウンタイマー

- `なし` / `3秒` / `5秒` / `10秒` から選択
- **選択は永続化する**（グリッドと同様）
- スイングは自撮りが基本のため必須機能。カウントダウン中は残り秒数を大きく表示する

### 2.5 録画時間の設定

- `5秒` / `10秒` / `20秒` / `30秒` から選択。**既定は10秒**
- **選択は永続化する**（グリッド・カウントダウンと同様）
- 「カウントダウン5秒 → 20秒録画」のように、2.4と組み合わせて動作すること

> **重要: 「録画の長さの上限」と「フレーム展開できる長さの上限」は別物である。**
>
> - **録画の長さ**: 技術的にきつい制約はない。20秒の1080p動画でも40〜60MB程度。上限30秒とするのは
>   ストレージへの配慮であって、それ以上の深い理由はない
> - **フレーム展開できる長さ**: 設計書の通り **10秒 / 600フレーム** が上限。
>   20秒×60fps=1200フレームは長辺1280pxのJPEGで約180MB/本（2本で360MB）となり、
>   展開処理に数十秒かかってUXが壊れる
>
> この2つは**トリミング**で橋渡しする。長めに撮っておき、展開前に必要な数秒だけを切り出す。
> **トリミングはフェーズ3.5で実装する。本フェーズでは実装しないこと。**
> （範囲を目で見て選ぶにはフレーム展開が前提のため、フェーズ3より前には作れない）
>
> したがって**本フェーズでは10秒を超えるクリップが保存され得るが、それは想定通りであり、
> 問題ではない。** フレーム展開自体がまだ存在しないため、この時点で不整合は起きない。

### 2.6 録画と保存

- 録画ボタンのタップで開始／停止
- **2.5で設定した秒数で自動停止する。** 録画中は残り時間を表示すること
- 設定秒数に達する前に手動で停止することもできる
- 撮影した動画は**アプリ専用ディレクトリの `videos/` 配下にコピーし、相対パスで保存する**
  （`ClipRepository` の既存の相対パス規約に従うこと）
- `durationMs` は**録画の実測経過時間**を入れる
- **`thumbnailPath` は `null` のままにする。** サムネイル生成はフレーム展開が必要なため**フェーズ3**。
  ライブラリは既にプレースホルダ表示に対応済み

### 2.7 取り込み（端末の動画から）

- ライブラリ画面のFAB付近に導線を置く（撮影と並ぶ形。UIの形は任せる）
- `image_picker` の `pickVideo(source: ImageSource.gallery)` を使う
- **取り込んだファイルは必ずアプリ専用ディレクトリの `videos/` 配下にコピーすること。**
  `image_picker` が返すパスは一時キャッシュ領域であり、**OSにいつ消されてもおかしくない**。
  返されたパスをそのまま `videoPath` に保存すると、後日クリップが再生不能になる
- **`durationMs` は `0`（不明）として保存してよい。**
  尺の取得には動画メタデータの読み出しが必要で、これは**フェーズ3のネイティブ層の担当**。
  そのために `video_player` を入れるのは本末転倒なので入れない。フェーズ3で埋める
- **ライブラリが `durationMs == 0` のときに表示を崩さないこと**（「—」等の表示にする）。
  既存の `_formatDuration` は `0.0秒` と表示してしまうため、対応が必要

### 2.8 設定の永続化

グリッド種類・カウントダウン秒数・録画時間の3つを保存する必要がある。

- **`shared_preferences` は使わない。** 新規パッケージを増やさず、
  既存の `ClipRepository` と同じ方式（アプリ専用ディレクトリのJSONファイル＋リポジトリクラス）で
  `settings.json` / `SettingsRepository` を作ること
- 理由: (1) 依存を増やさない (2) アトミック書き込み・壊れJSONからの復帰という既存の規律を揃える
  (3) フェーズ4で「比較ペアごとの位置合わせ結果」という構造化データを永続化する必要があり、
  そこで `shared_preferences` は不向き。今から同じ仕組みに寄せておく
- `ClipRepository` の実装（アトミック書き込み、`.broken` 退避、相対パス変換）を**踏襲すること**

### 2.9 権限の扱い

- `AndroidManifest.xml` に `CAMERA` を追加する。**`RECORD_AUDIO` は追加しない**（2.2参照）
- 権限が拒否された場合に**クラッシュさせない**。理由を説明し、設定アプリへ誘導する画面を出す
- 「二度と表示しない」で恒久拒否された場合も、同じ画面で行き止まりにならないこと

## 3. テスト（今回から必須）

**フェーズ1ではウィジェットテストが無く、UIが一度も実行されない状態で「完了」と報告された。
同じことを繰り返さないため、本フェーズではウィジェットテストを必須とする。**

- **撮影画面は、カメラプレビュー以外をウィジェットテスト可能な形に分離すること。**
  カメラは実機依存でテストできないが、**グリッド描画・カウントダウン・録画状態の管理は
  カメラから切り離せば純粋なDartとしてテストできる**。この分離を設計に織り込むこと
- 最低限、以下をカバーする単体／ウィジェットテストを書く:
  - グリッド種類を切り替えると描画パラメータが変わる
  - グリッド種類・カウントダウン秒数・**録画時間**が `SettingsRepository` に永続化され、読み戻せる
  - `settings.json` が壊れていても既定値で復帰し、`.broken` が残る
  - カウントダウンの状態遷移（開始 → 残り秒数の減少 → 録画開始）
  - **設定した録画時間で自動停止する**（5/10/20/30秒それぞれ。時間はテストで制御可能にすること）
  - **カウントダウンと録画時間の組み合わせが正しく動く**（例: 5秒待って20秒録画）
  - **ライブラリが `durationMs == 0` のクリップを表示しても落ちない／崩れない**
- 既存の5件のテストを**壊さないこと**
- `flutter analyze` を通すこと。警告を残さない
