## 1. 背景（なぜやるか）

録画は最長30秒までできるが、フレーム展開は10秒/600枚が上限。
30秒撮ったユーザーは、その中の「スイングの数秒」だけを比較したい。
現在は**先頭10秒が問答無用で使われる**ため、肝心の動作が後半にあると比較できない。

そこで**比較に使う範囲をユーザーが選べる**ようにする。

### 設計判断: 物理カットではなく「論理範囲」で実装する（重要）

動画ファイルを切り出して保存し直す方式は**採用しない**。理由:

1. 再エンコードには `MediaCodec` の変換パイプラインか ffmpeg が必要（ffmpegは禁止、
   MediaCodec変換は本アプリの規模に対して過剰に複雑でバグの温床）
2. 画質が劣化する
3. 元に戻せない（ユーザーが範囲を選び直せない）

代わりに、**クリップに「比較範囲（開始ms〜終了ms）」を記録し、フレーム展開時に
その範囲だけを展開する**。動画ファイルは一切触らない。これなら:

- エンコード不要・画質劣化ゼロ
- **何度でも範囲を選び直せる**
- 実装は「展開の開始位置をずらす」だけ（3bの均等サンプリングがそのまま使える）

**UI文言も「トリミング」ではなく「比較範囲」と呼ぶこと。**
「動画は切り取られません。比較に使う範囲を選ぶだけです」という位置づけをユーザーに伝える。

## 2. 具体的な作業内容

### 2.1 Pigeonインターフェースの拡張

`ExtractRequest` に範囲を追加する:

```dart
class ExtractRequest {
  // 既存フィールドはそのまま
  int? rangeStartMs;   // null なら先頭から
  int? rangeEndMs;     // null なら「開始+10秒相当」まで（現行と同じ挙動）
}
```

- Kotlin側は、範囲指定があればその区間を対象に均等サンプリングする
  （3bの「対象区間」が先頭10秒固定から可変になるだけ。サンプリングロジックは共通のまま）
- 範囲の長さが10秒/600枚を超える指定が来た場合は、**現行と同じ上限打ち切り**を適用する
- `probe` / `generateThumbnail` のシグネチャは**変えない**
- Pigeon生成物を再生成してコミットし、`docs/06_Pigeon生成手順.md` に追記する

### 2.2 データモデル（`Clip`）

```dart
final int? trimStartMs;  // 比較範囲の開始。null = 未設定（先頭から）
final int? trimEndMs;    // 比較範囲の終了。null = 未設定
```

- **JSONの後方互換を保つこと**（フィールドが無い旧 `clips.json` を読んでもクラッシュしない。
  3aの `isBroken` と同じやり方）
- バリデーション: `0 <= trimStartMs < trimEndMs <= durationMs`、かつ
  `trimEndMs - trimStartMs <= 10_000`。不正な値は保存時に弾く

### 2.3 キャッシュの整合（重要・事故りやすい）

**範囲が変わったら、古いフレームキャッシュは無効。** ここを漏らすと
「範囲を変えたのに前の範囲のフレームで比較される」という不具合になる。

- `manifest.json` に採用した範囲（`rangeStartMs`/`rangeEndMs`）を記録する
- キャッシュ完全性チェック（3bで実装済み）に**範囲の一致**を加える:
  クリップの現在の `trimStartMs`/`trimEndMs` とmanifestの範囲が一致しない → キャッシュ無効
- 無効になった古いキャッシュは、新しい展開の開始前に削除する
- **範囲を保存した時点で古いキャッシュを消す**（次回展開時ではなく即時。ストレージを無駄に
  占有させない）

### 2.4 範囲選択画面

ライブラリの長押しメニューに「**比較範囲を選択**」を追加（破損クリップには出さない）。

**プレビュー帯:**

- 動画**全体**から低解像度フレームを**まばらに**展開して横一列に並べ、タイムラインの
  背景にする（例: 最大24枚、長辺240px程度）
- これは既存の `extractFrames` を**小さいパラメータで呼ぶだけ**で実現できる
  （`maxFrames: 24, maxLongEdgePx: 240, rangeStartMs: 0, rangeEndMs: durationMs`）
- **プレビュー用の展開は比較用キャッシュ（`frames/<clipId>/`）と衝突させないこと。**
  別ディレクトリ（例: `frames_preview/<clipId>/`）に置き、同じ削除規律を適用する
  （クリップ削除時に一緒に消す）
- プレビュー展開中は進捗を出す（数秒で終わるはずだが無言にしない）。
  画面を閉じたらキャンセルする（3bのキャンセル機構を再利用）

**範囲の操作:**

- 開始・終了の**2つのハンドルをドラッグ**して範囲を選ぶ。選択範囲は視覚的に強調
- 選択中の長さを表示（例: 「選択中: 4.3秒」）
- **10秒を超える範囲は選べない**（ハンドルを制約するか、超過時に保存ボタンを無効化+理由表示。
  どちらか一貫した方式にし、報告に書く）
- ドラッグ中、ハンドル位置に最も近いプレビューフレームを大きく表示する
  （どの瞬間を指しているか分かるように。フレーム精度は不要、プレビュー帯の24枚で足りる）
- 初期表示: 既に範囲が設定済みならその範囲。未設定なら**先頭10秒**（現行の展開挙動と一致）
- 「リセット」で範囲設定を解除（null に戻す）できる
- 保存で `trimStartMs`/`trimEndMs` を永続化し、**古い比較用キャッシュを即時削除**

**画面の説明文:**

- 「動画は切り取られません。比較に使う範囲を選ぶだけで、あとから何度でも変更できます」
  の趣旨を画面内に一言入れる

**ライブラリ表示:**

- 範囲設定済みのクリップは、カードにそれが分かる表示を出す
  （例: はさみ/範囲アイコン + 「3.2秒 / 全体29.6秒」）。デザインの詳細は任せる

### 2.5 展開との統合

- 比較用の展開（開発用画面含む）は、クリップに範囲があれば**必ずその範囲で展開する**
- 範囲が未設定のクリップは現行通り（先頭から10秒相当）
- 10秒超のクリップを範囲未設定のまま展開した場合の挙動は現行維持
  （フェーズ4で「範囲を選んでください」と誘導する。本フェーズでは強制しない）

## 4. 実行と確認（実機必須）

- 実機: **Pixel 8 (Android 16)** / デバッグAPKは `adb install -r`（3b章と同じ手順）
- **確認すべき実機シナリオ（報告に結果を書くこと）:**
  1. 30秒クリップを撮影 → 「比較範囲を選択」→ プレビュー帯が表示される
  2. 後半の5秒を選んで保存 → 開発用画面で展開 → **展開されたフレームが選んだ範囲の映像**
     である（先頭10秒ではない）ことを目視で確認
  3. 範囲を変えて保存 → 古いキャッシュが消え、再展開で新しい範囲になる
  4. 範囲一致のまま再展開 → キャッシュから即座に出る（無駄な再展開なし）
  5. リセット → 範囲解除され、現行の先頭10秒挙動に戻る
  6. 範囲設定済みクリップの削除 → 動画・サムネイル・比較キャッシュ・**プレビューキャッシュ**が
     すべて消える
  7. 破損クリップに「比較範囲を選択」が出ない
  8. **範囲選択画面の閉じ方の全経路**（保存 / 戻るキー / プレビュー展開中に閉じる）で
     クラッシュしない
- **ダイアログ・画面は「閉じ方の全経路」を必ず検証すること。**
  フェーズ3b検証で、メモダイアログを「外側タップで閉じる」経路だけがクラッシュする
  フェーズ1由来のバグが見つかった。ボタンで閉じて動いた≠安全、である

- ❌ 上限（10秒/600枚）自体を変更・撤廃すること
- ❌ `probe` / `generateThumbnail` のシグネチャ変更
- ❌ プレビュー展開を比較用キャッシュと同じディレクトリに混ぜること
- ❌ 範囲変更後も古いキャッシュを残すこと
- ❌ 相対パス規約・アトミック書き込み規約を破ること
- ❌ UI層からPigeon/ネイティブを直接叩くこと（サービス層経由）
- ❌ メインスレッドでの展開 / `release()` 漏れ / Bitmap一括保持（3bの規律を維持）
- ❌ iOS向けの実装 / `minSdkVersion`・applicationId の変更 / フォルダ移動
