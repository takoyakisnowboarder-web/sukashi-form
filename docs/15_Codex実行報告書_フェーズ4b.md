## 変更ファイルと差分の要点

- `lib/screens/compare_screen.dart`
  - フェーズ4aのA/B縦並び仮表示を、透過モードと分割モードの表示層へ置き換えた。
  - 画面上部に透過／分割セグメントを追加した。切替時は同じ`ComparisonController`を保持し、再生位置・同期・変換を変更しない。
  - 透過モードはAの上へBを重ね、Bの不透明度を0〜100%で操作できる。
  - 分割モードは50:50固定で、上下／左右を切り替えられる。
  - 位置合わせモード、対象A/B、ドラッグ移動、ピンチ拡縮、2本指回転、リセットを追加した。位置合わせ中は通常のシーク・再生操作を隠して排他にした。

  - フェーズ4aのデバッグ用フレーム番号表示を削除した。
  - 再生・同期・コマ送りの計算は変更せず、フェーズ4aの共通コントローラだけを使用している。
- `lib/widgets/comparison_frame_view.dart`
  - A/B共通の薄いフレーム表示ウィジェットを追加した。
  - `Transform.translate`、`Transform.rotate`、`Transform.scale`を表示にだけ適用する。
  - `Image.file(cacheWidth: ...)`を指定し、フレーム画像ファイル自体は変更しない。
- `lib/models/comparison_pair.dart`
  - 既存version 1 JSONへ後方互換で`hasSynchronizedReference`、`splitAxis`、`overlayOpacity`を追加した。
  - 未同期ペアでも変換・分割軸・透過率だけを保存できるようにした。
  - フェーズ4aの旧JSONは「同期済み・上下分割・透過50%」として読み込む。
- `lib/data/comparison_pair_repository.dart`
  - 未同期ペアでは基準時刻の範囲検証を行わず、表示設定を保持するようにした。
  - 同期済みペアの範囲変更時無効化と、クリップ削除時のペア削除は従来どおり維持した。
- `test/compare_screen_test.dart`
  - 変換行列、`cacheWidth`、透過率反映、分割軸、モード切替時の時刻・変換維持、通常操作との排他、リセット、実2ポインタ相当の拡縮・回転を追加した。
- `test/comparison_pair_repository_test.dart`

## 実機での動作確認

端末: Pixel 8 / Android 16 / API 36 / 端末ID `3C041FDJH0038Z`

アプリ自身で4.852秒、4.659秒、9.626秒の正常クリップを撮影し、`adb install -r`でデータを保持して確認した。

1. 透過モード
   - 4.852秒／4.659秒の2本を重ねて表示した。
   - B透過スライダーを50%（初期値）、0%、100%へ変更し、UI値が`0%, 0%`／`100%, 100%`となり、Bの重なりが消える／完全表示になることを確認した。
   - 透過率は`comparison_pairs.json`にも保存された。
2. 分割モード
   - 上下分割ではAが上、Bが下へ50:50で表示された。
   - 左右へ切り替えるとAが左、Bが右へ変わった。
   - 左右分割のまま連動再生し、共通シーク位置が48%まで進んだ。分割軸は`horizontal`として保存された。
3. モード切替で状態維持
   - A/B同期基準を設定し、共通シークを69%へ進めてから分割→透過へ切り替えた。
   - 切替前後とも`同期済み`かつシーク69%であり、再生位置と同期状態を維持した。
   - 逆方向の透過→分割も同じコントローラ状態を維持した。
4. 位置合わせ
   - 位置合わせONで通常シーク・再生操作が消え、対象A/B・リセット・完了だけが表示された。
   - Bを実機上でドラッグし、保存値が`dx=38.4, dy=38.4`へ変化した。リセット後は`dx=0, dy=0, scale=1, rotation=0`へ戻った。
   - Android標準UIAutomatorの実2ポインタジェスチャーを映像領域へ注入し、Bが`scale=2.2007, rotation=-5.6149rad`へ変化したため、ピンチ拡縮と2本指回転の両方を実機で確認できた。
   - 完了後は通常スライダーへ戻った。
5. 再起動復元
   - 透過率80%、左右分割、B移動`dx=25.6, dy=12.8`、同期基準を保存した。
   - アプリを強制終了・再起動し同じ2本を選ぶと、`同期済み`、透過80%、左右選択、B変換が復元された。
6. メモリ
   - 透過モード1.0x再生中に`dumpsys meminfo`を10回採取した。
   - 最大TOTAL PSSは690,766KB、中央値は約603,521KB、最大TOTAL RSSは807,444KB、最大SWAP PSSは83KBだった。OOM、強制終了、表示停止はない。
   - フェーズ4a実行報告書の同一端末実測ピーク839,801KBから149,035KB減（17.7%減）となった。
   - 指示書本文の参考値620〜660MBに対しては、一時ピーク690,766KBが上限を約30MB超えた。10試料の多くは577〜615MBで、666／676／691MBの一時上昇が最大値を押し上げた。`cacheWidth`適用と64MB imageCacheにより実測ベースでは4aより低下しているが、debugビルドのGCタイミングによる振れは残る。
7. SafeArea
   - 透過スライダー、上下／左右トグル、位置合わせ説明の各最下端は物理Y=2225pxだった。
   - AndroidナビゲーションバーはY=2250pxからで、25pxの間隔がある。要素の重なり、誤タップによるホーム遷移はなかった。
8. 閉じ方の全経路
   - 透過モード再生中、分割モード、位置合わせON、フレーム展開開始350ms後に戻る操作を実施した。
   - すべてライブラリへ復帰し、`FATAL EXCEPTION`、`FlutterError`、接続断はなかった。
   - 展開中に閉じたクリップのフレームディレクトリは残らず、キャンセルを確認した。
9. 異なる長さ・同期あり／なし

## 設計上の判断

- モードは画面の表示状態だけとし、タイムライン・同期・コマ送り・ループ・速度は既存`ComparisonController`を共有した。
- 変換はクリップID単位でコントローラへ設定し、描画時に共通`ComparisonFrameView`で適用した。透過／分割それぞれに変換ロジックを複製していない。
- 未同期でも位置合わせを保存できるよう、同期済みかどうかをJSONへ明示した。旧JSONは同期基準2件を持つため、フィールド欠落時を`true`として後方互換を維持した。
- 透過率は任意項目だったが、実機シナリオの再起動復元対象に含まれるためペア設定へ保存した。
- `cacheWidth`はPixel 8の画面物理解像度相当を上限1280pxの範囲で算出し、現在表示と先読みの`ResizeImage`で同じ値を使用した。

## 逸脱・迷った点
