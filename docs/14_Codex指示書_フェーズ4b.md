## 1. 背景と設計の骨子

> 設計書6章の禁止事項: 透過モードと分割モードで再生ロジックを二重に書かない。
> 同期・コマ送り・ループ・速度・位置合わせは単一の共通コントローラが持ち、
> 表示モードはその上に乗る薄い表示層とする。

4aでコントローラは完成済み。**本フェーズの表示モードは、コントローラから
「今表示すべきA/Bのフレーム」と「A/Bの変換」を受け取って描くだけの薄い層**にする。
透過モードと分割モードは**同じ入力（同じフレーム・同じ変換・同じ再生状態）を別レイアウトで
描くだけ**であり、再生ロジックを各モードに複製してはならない。

**モードを切り替えても、再生位置・基準同期・位置合わせは一切リセットしない**
（すべてコントローラ側の状態なので、表示層を差し替えても保持される。これが4a/4b分離の狙い）。

## 2. 具体的な作業内容

### 2.1 モード切替

- 画面上部にセグメントコントロール等で **透過モード / 分割モード** を切り替える
- **切替時に再生位置・同期・位置合わせを維持**（コントローラの状態は触らない）
- 現在どちらのモードかが一目で分かること

### 2.2 透過モード（設計書3.3.1）

- 映像エリアに A を表示し、その上に B を**重ねて**表示する
- **透過スライダー: B の不透明度 0〜100%**。画面下部に大きく配置し、
  片手の親指で操作できる位置に置く
- **透過スライダーはこのモードでのみ表示**（分割モードでは出さない）
- 透過率の初期値は50%程度でよい。透過率はペアに保存してよい（任意。しなくても可）

### 2.3 分割モード（設計書3.3.2）

- 画面を**上下2分割**（既定）し、上にA・下にBを表示して同時再生
- 分割比率は50:50固定（v1では仕切りドラッグ変更なし）
- **上下 / 左右の切替トグル**を用意する（レイアウトの軸を差し替えるだけ）
- **上下/左右の選択はペアに保存**して次回復元する

### 2.4 位置合わせ（設計書3.3.5・両モード共通）

- **A/Bそれぞれに変換**（平行移動dx,dy / 拡大縮小scale / 回転rotation）を適用して表示する。
  変換データは**4aで用意済みのスロット**（`comparison_pair.json`のtransforms）を使う
- **「位置合わせモード」のトグル**でオン/オフ。通常時に誤操作しないよう明確に分離すること
  - 位置合わせモードOFF時: スライダー/シーク等の通常操作
  - 位置合わせモードON時: 映像エリアのジェスチャーで変換を操作
- ジェスチャー: **ドラッグで平行移動 / ピンチで拡大縮小 / 2本指回転**
  - 透過モードでは基本 B を合わせる。ただし内部的にはA/B個別に持つ（下記トグルで対象切替）
  - **どちらのクリップを操作対象にするかのトグル**（A / B）を位置合わせモード時に出す
- **リセットボタン**（対象クリップの変換を恒等値に戻す）
- 合わせた結果は**ペアごとに保存**し、次回同じ2本を開いたときに復元する
  （4aの永続化に相乗り。保存経路は既存の `ComparisonPairRepository` を使う）
- 変換は**表示にのみ適用**。フレーム画像ファイルは書き換えない（論理変換）

### 2.5 メモリ対策（必須・4aからの持ち越し）

4aでフレームがフル解像度(1280px)デコードされ、再生中PSSが高め(debug 620MB)だった。
**本フェーズでは必ず対処すること。**

- フレーム表示（`Image.file` / `FileImage`）に **`cacheWidth`（または`cacheHeight`）を指定**し、
  **実際の表示解像度でデコード**する（画面幅を超える解像度でデコードしない）
- 先読み（precache）にも同じ `cacheWidth` を適用する
- 透過モードは2枚を重ねるため、無指定だと4aより悪化する。ここを外すとOOMに近づく
- **対処後、再生中の `dumpsys meminfo` ピークを4a（PSS約620-660MB）と比較して報告すること**
  （下がっているはず。下がっていなければ原因を調査）

### 2.6 SafeArea（必須・過去3回の教訓）

- **画面最下部の操作要素（スライダー・ボタン・トグル）は、必ず
  SafeAreaのbottom inset（`MediaQuery.viewPaddingOf(context).bottom`）を考慮する。**
- フェーズ3aのボトムバーはみ出し、3bのダイアログ、4aの同期ボタンがナビバーと重なる問題、と
  **画面最下部の扱いで3回連続で不具合が出ている**。最下部にコントロールを置くこのフェーズは
  最も危険。実機でナビゲーションバー（ジェスチャー領域含む）と重ならないことを必ず確認する

### 2.7 その他

- 4aのデバッグ用フレーム番号表示（A: 37/114 等）は**本フェーズで消す**
  （本表示に不要。コントローラ側のAPIは残してよいが、画面には出さない）
- 縦持ち動画のフレームは既に正しい向きで展開されている（3bで対応済み）。
  変換の回転(rotation)は**ユーザーの位置合わせ用**であり、動画の向き補正とは別物

- **位置合わせモードのトグル**: ON/OFFで通常操作とジェスチャー操作が排他になる

## 4. 実行と確認（実機必須）

- 実機: **Pixel 8 (Android 16)** / `adb install -r`（従来手順）
- **確認すべき実機シナリオ（報告に結果を書くこと）:**
  1. 2本を比較 → **透過モード**でBの透過スライダーを0/50/100%に動かし、重なりが変化する
  2. **分割モード**に切替 → 上下2分割で同時再生 → **上下/左右トグル**で軸が変わる
  3. **モード切替で状態維持**: 透過で再生位置を進め基準同期した状態から分割へ切替 →
     再生位置・同期が保たれている（逆方向も）
  4. **位置合わせ**: 位置合わせモードON → Bをドラッグ/ピンチ/回転で動かせる →
     リセットで戻る → OFFにして通常操作に戻れる
  5. 位置合わせ・透過率・分割軸を設定 → **アプリ再起動して同じ2本を開くと全部復元される**
  6. **メモリ**: 透過モード再生中の `dumpsys meminfo` ピークを測定し、4a(620-660MB)と比較
  7. **SafeArea**: 最下部のスライダー/ボタン/トグルがナビバーと重ならず、誤タップでホームに
     戻らない（4aで実際に起きた不具合の回帰確認）
  8. **閉じ方の全経路**: 各モード・位置合わせモードON中・展開中に戻る。いずれもクラッシュしない
  9. 長さの違う2本、基準同期あり/なし、でモード切替しても破綻しない
