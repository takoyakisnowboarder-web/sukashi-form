### なぜフェーズ3を3aと3bに分けるか

フェーズ3は本アプリの技術的な心臓部であり、一度に全部やると検証が雑になる。
（フェーズ1では大きなスコープを一度に投げた結果、UIが一度も実行されないまま「完了」と報告された）

3aは**プロジェクト初のネイティブコード**であり、ここで配線を確実に通しておけば、

**ライブラリにサムネイルが出る／取り込み動画の尺が埋まる／壊れたクリップが分かる**という
目に見える成果が出るため、検証もしやすい。

## 1. 背景（なぜやるか）

現状、以下の3つが未解決で残っている。すべて**動画のメタデータをネイティブで読めれば解決する**。

1. **サムネイルが出ない。** `thumbnailPath` は常に `null` で、ライブラリは灰色のプレースホルダのまま。

   フェーズ3bのフレーム展開でそのまま失敗する

本フェーズでネイティブ層の配線（Pigeon）を通し、この3つを片付ける。

### 2.1 依存パッケージ（追加の許可リスト）

既存（`flutter_riverpod` / `go_router` / `path_provider` / `uuid` / `intl` / `camera` /
`image_picker`）に加えて、以下**のみ**を追加してよい。

| パッケージ | 種別 | 用途 |
|---|---|---|
| `pigeon` | **dev_dependency** | Flutter↔ネイティブの型安全なインターフェース生成 |

> **重要: Pigeonは禁止している「コード生成系」に該当しない。**
> `build_runner` / `freezed` / `json_serializable` を禁じているのは、**ビルドに常時介入する
> codegenパイプラインを増やしたくない**ため。Pigeonは**手動で1回叩くCLI**であり、
> 生成物をリポジトリにコミットして使う。ビルドプロセスには一切介入しない。
> **`build_runner` は今回も導入しないこと。**

**禁止（継続）:** `ffmpeg_kit_flutter` 系、`build_runner`/`freezed`/`json_serializable`、
`shared_preferences`、`permission_handler`、`video_player`、Riverpod以外の状態管理、
通信・アナリティクス・広告・クラッシュレポートSDK。

### 2.2 Pigeonインターフェースの定義

`pigeons/frame_extractor.dart` に定義する。**本フェーズで使うのは `probe` のみだが、
フェーズ3bで使う `extractFrames` / `deleteCache` もインターフェースだけ先に定義してよい**
（実装は3b。3aでは `UnimplementedError` を投げるスタブに留める）。

想定する形（詳細は任せるが、この意図を満たすこと）:

```dart
class VideoInfo {
  bool isValid;        // 読めない/0バイト/尺0 なら false
  int durationMs;      // 不明なら 0
  int width;
  int height;
  int? rotationDegrees;
  String? errorReason; // isValid == false のとき、原因を短く（ログ・報告用）
}

@HostApi()
abstract class FrameExtractorApi {
  @async
  VideoInfo probe(String absoluteVideoPath);

  @async
  String generateThumbnail(String absoluteVideoPath, String absoluteOutputPath, int maxLongEdgePx);
}
```

- 生成物のパス: Dart側 `lib/native/frame_extractor.g.dart`、
  Kotlin側 `android/app/src/main/kotlin/.../FrameExtractorApi.g.kt`
- **生成物はリポジトリにコミットすること**
- **生成コマンドを `docs/` 配下か `README.md` に必ず記録すること。**
  記録がないと、次に誰も再生成できない

### 2.3 Android実装（Kotlin）

`MediaMetadataRetriever` を使う。

- **必ず `try/finally`（または `use`）で `release()` すること。** 解放漏れはネイティブリークになる
- **メインスレッドで動画を読まないこと。** `MediaMetadataRetriever` は重い。
  バックグラウンド（コルーチンやExecutor）で実行し、結果をメインスレッドで返す
- `probe` は例外を投げずに `VideoInfo(isValid: false, errorReason: ...)` を返すこと。
  **ネイティブ例外をDart側に投げ返してクラッシュさせない**
- `isValid == false` とすべき条件（最低限）:
  - ファイルが存在しない
  - **ファイルサイズが0バイト**
  - `MediaMetadataRetriever.setDataSource` が例外を投げる
  - `METADATA_KEY_DURATION` が取れない、または 0 以下
- サムネイルは `getFrameAtTime`（または `getScaledFrameAtTime`）で先頭付近の1フレームを取り、
  **長辺 `maxLongEdgePx`（既定512程度）に縮小してJPEGで保存**する。
  一覧のサムネイルに元解像度は不要

> **注意:** `getFramesAtIndex`（フェーズ3bで使う）は API 28 以上を要求する。
> 本プロジェクトの `minSdkVersion` は 28 なので問題ないが、**3aでは使わない。**

### 2.4 iOS実装

- **インターフェースだけ用意し、実装は空スタブ**とする（`FlutterError` / 未実装例外を返す）
- 将来 `AVAssetImageGenerator` でそのまま差し込めるよう、**インターフェースを共通のまま保つこと**
  （この移植しやすさが設計要件。iOS固有の都合をインターフェースに持ち込まない）
- **iOSビルドの検証は不要。** 着手しないこと

### 2.5 Dart側のサービス

`VideoMetadataService`（名前は任せる）を作り、Pigeon APIをラップする。**UI層からPigeonを直接叩かせない。**

- 相対パス → 絶対パスの変換は既存の `ClipRepository.resolveAbsolutePath` を使う
  （**Pigeonには絶対パスを渡し、`Clip` には相対パスを保存する**という既存規約を守る）
- サムネイルの保存先: アプリ専用ディレクトリの `thumbnails/<clipId>.jpg`。
  `Clip.thumbnailPath` には**相対パス**を入れる
- **UI層はこのサービス経由でのみネイティブに触ること**（3bで実装が変わってもUIに波及させないため）

### 2.6 サムネイルと尺の穴埋め（backfill）

- **新規クリップ**（撮影・取り込みの両方）を保存した直後に、probe → サムネイル生成 → 
  `thumbnailPath` と `durationMs` を更新する
- **既存クリップ**で `thumbnailPath == null` または `durationMs == 0` のものは、
  **ライブラリ表示時に非同期で穴埋めする**
  - 一覧の表示を**ブロックしないこと**。先にプレースホルダで一覧を出し、
    埋まったものから順に差し替わる形にする
  - 同じクリップに対して**穴埋め処理が多重に走らないようにすること**
- **撮影・取り込みと穴埋めは同じコードパスを通すこと。** 二重実装しない

### 2.7 壊れたクリップの扱い

`probe` が `isValid == false` を返したクリップは、**黙って消さない。ユーザーに見せる。**

- ライブラリのカードに「**この動画は読み込めません**」と分かる表示を出す
- そのクリップは**比較の選択対象から外す**（選ぼうとしても選べない、または選択時に警告）
- 長押しメニューから削除できること（既存の削除導線で足りるならそれでよい）
- **自動削除は禁止。** ユーザーのデータを勝手に消さない。判断はユーザーに委ねる
- `Clip` に検証結果を保持するフィールドを足してよい（例: `isBroken`）。
  ただし**JSONの後方互換を保つこと**（フィールドが無い旧JSONを読んでもクラッシュしない）
