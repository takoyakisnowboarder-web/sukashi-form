## 1. 背景と設計判断（実装前に理解すること）

比較画面はこのアプリの主役であり、その心臓が**2本のフレーム列を同期させて動かす
コントローラ**である。表示（重ねる/並べる）はフェーズ4bで作るが、
再生・同期・コマ送りのロジックは**すべて本フェーズの単一コントローラに集約する**。

> 設計書の禁止事項(6章)より: 透過モードと分割モードで再生ロジックを二重に書かない。
> 同期・コマ送り・ループ・速度・位置合わせは単一の共通コントローラが持ち、
> 表示モードはその上に乗る薄い表示層とする。**この構造を作るのが本フェーズである。**

### 1.1 タイムラインは「時間(ms)」で持つ。フレーム番号で持たない（最重要）

2本のクリップはfpsが異なり得る（例: 29.81fps と 30.02fps。標準カメラのスロー動画の
取り込みなら120fps超もあり得る）。フレーム番号同士を対応させると必ずズレが蓄積する。

- 各クリップの展開フレーム `i` は、manifest（範囲・枚数）から
  **クリップ内時刻**に変換できる: `timeOf(i) = rangeStart + i * (rangeLength / frameCount)`
- マスター時刻 `τ`（比較タイムライン）を1本持ち、**各クリップは
  「自分の基準時刻 + τ」に最も近いフレーム**を表示する（nearest-frame検索）
- 基準フレーム同期は「A の基準時刻 refA / B の基準時刻 refB」を記録し、
  `τ = 0` がその瞬間になるよう対応付けるだけ。オフセット計算はすべてms単位

### 1.2 再生範囲は2本の交差（intersection）とする

基準を合わせると、2本の再生可能範囲はズレる（Aは基準前1秒しかないがBは3秒ある、等）。

- **v1では、両方に実フレームが存在する範囲（交差）だけを再生・シーク対象にする**
- 理由: 片方だけが動き片方が凍る表示は、重ね比較では混乱のもと。
  交差なら「今見ている瞬間は必ず両方の実映像」という保証が立つ
- 交差が空（基準の取り方で重なりゼロ）の場合はエラーにせず、
  「重なる区間がありません。基準を取り直してください」と案内する

### 1.3 位置合わせは「データだけ」本フェーズ、「操作UI」は4b

ドラッグ/ピンチ/回転のジェスチャーは表示モードと密結合のため4bで作る。
本フェーズでは**変換データ（平行移動dx,dy / 拡大率 / 回転角）をクリップごとに持つモデルと
永続化、コントローラ上の状態スロット**だけを用意する。仮表示は変換を適用しなくてよい。

## 2. 具体的な作業内容

### 2.1 比較コントローラ（純粋Dart。本フェーズの主成果物）

`ComparisonController`（名前は任せる）を**UIから完全に分離した純粋Dartクラス**として実装する
（`capture_session_machine` と同じ流儀。テスト可能性が最優先）。

**入力:** 2クリップ分のフレーム情報（各フレームのファイルパスとクリップ内時刻のリスト、
manifest由来）。ネイティブやファイルI/Oに依存しないこと（パスは文字列として扱うだけ）。

**状態と操作:**

- マスター時刻 `τ`、再生中/停止、ループ（**既定ON**）、速度（**0.25x / 0.5x / 1x**）
- 現在の各クリップの表示フレームindex（nearest-frame。**単調性を保証**:
  τが進めばindexは戻らない）
- **コマ送り ◀▶**: 1ステップ = **2本のフレーム間隔の細かい方**。
  ステップごとに少なくとも一方のクリップのフレームが変わる。
  「進めて戻すと同じフレームに戻る」こと（往復一貫性）
- **基準フレーム同期**: `setReference(clipId, ms)` を2本分。両方設定されたら
  オフセット再計算 + 再生範囲（交差）再計算。未設定時の既定は**範囲の先頭同士を揃える**
- シーク（交差範囲内にクランプ）
- 再生クロックは**外部から時間を注入できる形**にする（`tick(elapsed)` 等）。
  実UIではTickerから駆動し、テストでは手動で時間を進める

### 2.2 比較ペアの永続化

「同じ2本を開いたら前回の設定を復元」のための保存層。

- `ComparisonPairRepository` + `comparison_pairs.json`（既存リポジトリと同じ規律:
  アトミック書き込み・`.broken` 退避・相対パスのみ・UIから直接I/O禁止）
- キーは**クリップIDのペア（順序を正規化=ソートして保存）**。選択順が逆でも同じ設定を引く
- 保存する値: 各クリップの基準時刻(ms)、各クリップの位置合わせ変換（dx, dy, scale,
  rotation。本フェーズでは常に恒等値でよい）
- **整合性検証**: 読み込んだ基準時刻がそのクリップの**現在の展開範囲外**なら
  （範囲を選び直した等）、そのペアの保存値は**破棄して既定に戻す**（黙って使わない）
- クリップ削除時、そのクリップを含むペア設定も削除する

### 2.3 比較画面（仮表示。作り込まない）

`/compare` のスタブを置き換える。**表示は4bで全面的に差し替える前提の仮画面**であり、
上下に2枚のフレームを並べるだけの最小構成とする（パン/ズーム/透過/トグル等は一切なし）。

- **入場時の準備フロー:**
  1. 2クリップのどちらかが `durationMs > 10_000` かつ範囲未設定なら、
     「このクリップは10秒を超えています。比較範囲を選択してください」と案内し、
     範囲選択画面へ誘導する（戻ってきたら続行）
  2. フレーム未展開のクリップは**1本ずつ順に**展開する（並行しない。メモリ配慮）。
     進捗は「1/2本目: N/M フレーム」形式で出す。**展開中に画面を離れたらキャンセル**
     （3bのキャンセル機構を再利用）
  3. 展開済みならキャッシュから即座に開始
- **仮表示の内容:**
  - 上=A / 下=B のフレーム表示（`Image.file`）
  - 共通シークバー（交差範囲）
  - 再生/一時停止、◀▶ コマ送り、ループON/OFF、速度切替（0.25/0.5/1x）
  - **デバッグ用にフレーム番号表示**（例: A: 37/114 B: 52/150）。
    コマ送りの正確性を実機で目視検証するために必須。4bで消す
- **基準フレーム同期のUI**（設計書3.3.4の手順に従う）:
  - 「基準を合わせる」→ ステップ1: Aだけをスクラブして「ここを基準にする」→
    ステップ2: Bだけをスクラブして「ここを基準にする」→ 同期完了、連動再生に戻る
  - 同期済みかどうかが画面上で分かること。「基準を取り直す」で再設定できること
  - 途中でキャンセルしたら元の状態に戻る（中途半端な片側だけの基準を残さない）
- **再生パフォーマンス**: 再生中は次の数フレーム（各クリップ4〜8枚程度）を
  `precacheImage`等で先読みしてよい。**全フレームの先読みは禁止**（OOM）。
  `main.dart` のimageCache上限を変更する場合は理由と新値を報告に書くこと

### 2.4 ライブラリからの導線

- 既存の「2本選択 → 比較する」の遷移先を新画面に差し替えるだけ。選択仕様は変えない

## 3. テスト（必須）

コントローラが純粋Dartなので、同期ロジックは徹底的にテストできる。**ここが本丸。**

- **同期計算**: 基準設定→オフセット→交差範囲が正しい（fpsが異なる2本で検証。
  例: 29.8fps/114枚 と 30.0fps/150枚）
- **nearest-frame**: τに対する各クリップのフレームindexが正しい。単調性
- **コマ送り**: 1ステップで少なくとも一方が変わる / 往復一貫性 / 交差端で止まる
- **再生**: `tick` 駆動で速度0.25/0.5/1xが正しく反映。ループONで交差端から先頭へ戻る
- **基準未設定の既定**（先頭揃え）と、片側だけ設定の中間状態の扱い
- **交差が空**のケース（エラーにならず検出できる）
- **ペア永続化**: 往復一致 / ID順序を入れ替えても同じ設定を引く /
  範囲外の基準時刻は破棄される / クリップ削除でペア設定も消える / 壊れJSONで既定復帰
- **ウィジェット**: 準備フロー（範囲未設定の10秒超→誘導 / 展開進捗表示）、
  基準設定フローのキャンセルで状態が戻ること
- 既存43件を壊さない / `flutter analyze` クリーン

## 4. 実行と確認（実機必須）

- 実機: **Pixel 8 (Android 16)** / `adb install -r`（従来手順）
- **確認すべき実機シナリオ（報告に結果を書くこと）:**
  1. 5秒クリップを2本撮影 → 比較 → 順に展開（進捗表示）→ 連動再生・ループ・速度切替
  2. **コマ送り ◀▶ でフレーム番号表示が1ステップずつ正確に動く**（往復して同じ番号に戻る）
  3. 基準フレーム同期: A→Bの順で基準を設定 → τ=0で両方の基準フレームが表示される →
     **アプリを再起動して同じ2本を開くと同期が復元されている**
  4. 選択順を入れ替えて（B,Aの順で選択）開いても同じ同期設定が使われる
  5. 長さの違う2本（例: 5秒と10秒）→ シーク範囲が交差に制限され、端でクラッシュしない
  6. 10秒超・範囲未設定のクリップで比較開始 → 範囲選択へ誘導され、設定後に比較できる
  7. 基準設定済みのクリップの範囲を変更 → 再度比較を開くと保存済み同期が破棄され既定に戻る
  8. **閉じ方の全経路**: 展開中に戻る / 再生中に戻る / 基準設定ステップの途中で戻る。
     いずれもクラッシュしない
  9. 再生中の `dumpsys meminfo`（2本同時デコードのピークを報告。OOMしないこと）
