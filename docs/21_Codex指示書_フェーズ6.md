## 1. UI改修（モックの5画面に対応）

### 1.1 撮影画面（モック1）

- **録画ボタンを下段の水平中央**に配置。左=カウントダウンタイマー、右=録画秒数
- **グリッド選択を画面右上のチップ**へ移動（左上の✕の反対側。タップで種類が巡回する現行仕様のまま）
- 下段は「タイマー | ●録画 | 録画秒数」の3点のみ
- 加えて**ギャラリー自動保存のON/OFFチップ**を右上のグリッドチップの近くに置く（2.1参照）。
  収まりが悪ければ配置を工夫してよいが、変更した場合は報告に書く

### 1.2 比較範囲の選択画面（モック2）

- **動画プレビューを画面の大半に拡大**（縦方向の残り領域をすべて使う）
- その下にフィルム帯+範囲ハンドル（操作仕様は現行のまま）、選択秒数表示、保存/リセット
- **説明文（「動画は切り取られません…」）は右上の「?」ボタンに格納**。
  押すとダイアログ等で表示。常時表示はしない

### 1.3 比較画面・通常時（モック3）

- **常時表示は4つだけ**: 映像 / 再生リモコン / シークバー / 透過・分割の切替
- 上段: ←戻る、透過/分割セグメント（中央）、「?」、設定ボタン（右端）
- **映像領域を最大化**（幅いっぱい・縦も可能な限り）
- シークバー右に **現在/全体の秒数**（例「1.2 / 4.8秒」、`tabular-nums`相当の等幅で）
- **リモコン3つ（1コマ戻る / 再生・一時停止 / 1コマ進む）を横一列いっぱいに大型化**。
  再生ボタンは一回り大きく（モック比: 66px/80px 目安）
- 従来ここにあった ループ・速度・透過スライダー・位置合わせ・同期の行は**すべて撤去**し設定シートへ

### 1.4 設定シート（モック4）

- 上段右端の設定ボタンで**下からボトムシート**が開く
- 中身: ループON/OFF / 速度(0.25/0.5/1.0) / B透過スライダー / 位置合わせを開始 / 同期状態と基準の再設定
- **B透過スライダーは透過モード時のみ表示**（現行仕様の維持）
- シート外タップ・下スワイプで閉じる。**シートを開閉しても再生状態を変えない**
- 「速度」はモック通り**独立した行**にする（1行に詰め込まない）

### 1.5 位置合わせモード（モック5）

- **「位置合わせ対象 A/B」の選択ボタンを廃止**し、直接操作にする:
  - **分割モード: 触ったペインの映像が動く**（Aを触ればA、Bを触ればB）
  - **透過モード: 上のレイヤー(B)が動く**。どちらが動くか枠線等で明示
- 操作ヒント（ドラッグ/ピンチ/2本指回転）は上部のチップ1つに集約
- 下段は「リセット | 完了」のみ。リセットは**操作対象になっている側**を恒等値に戻す
  （両方戻したい場合の扱いは任せるが、報告に書く）
- 位置合わせモードのON/OFF自体は維持（通常時の誤操作防止。4bと同じ）
- ジェスチャー→変換→ペア保存の仕組みは4bのまま。**入口のUIだけ変える**

### 1.6 「?」ヘルプの内容

- 比較範囲画面: 現行の説明文（動画は切り取られない/何度でも変更可）
- 比較画面: 透過/分割の意味、基準同期とは何か、位置合わせの操作方法、を簡潔に
- 文面はCodexが下書きしてよい（**実装にない機能に触れないこと**）

## 2. 撮影体験の強化（新機能2つ）

### 2.1 撮影した生データのギャラリー自動保存

**現状、動画はアプリ専用領域にのみ保存され、アプリを消すと消える。**
撮影のたびに端末のギャラリー（フォト）にもコピーを残せるようにする。

- **タイミング: 録画完了のたびに自動保存**。取り込み動画は対象外（元から端末にあるため）
- **設定でOFFにできる**（`SettingsRepository` に項目追加。**既定はON**）。
  トグルUIは撮影画面右上（1.1参照）
- 実装: **`MediaStore.Video` への挿入**（Pigeonに小さなHost APIを追加し、Kotlin側で実装）
  - `RELATIVE_PATH` は `Movies/スカシフォーム`（または `DCIM/スカシフォーム`。選択理由を報告）
  - **API 29以上のみ対応。新しい権限は一切追加しない**（自アプリ作成メディアのMediaStore挿入は
    権限不要）。API 28（Android 9）では設定自体を非表示にし、理由をコードコメントに書く
  - `IS_PENDING` を使い、書き込み完了後に確定する（途中で落ちても壊れたファイルを見せない）
- **失敗しても録画は失敗にしない**: ライブラリへの保存（現行処理）が主で、ギャラリーは副。
  ギャラリー保存に失敗したらスナックバー等で知らせ、クリップ自体は残す
- **アプリ内でクリップを削除しても、ギャラリーのコピーは消さない**（ユーザーの資産）
- プライバシーポリシー（`docs/18`）との整合: 「端末内にのみ保存」の記述に
  「ユーザーが有効にした場合、端末のギャラリーにも保存されます」相当の追記が必要。
  **下書きの修正案を報告に含める**（確定はオーナー）

### 2.2 音量キーで録画開始/停止（Bluetoothリモコン対応）

- **撮影画面が表示されている間だけ**、音量キー上下のどちらでも:
  - 待機中 → **画面の録画ボタンとまったく同じ動作**（タイマー設定があればカウントダウン開始）
  - 録画中 → **録画停止**（画面ボタンと同じ）
  - カウントダウン中 → 画面の録画ボタンと同じ挙動に合わせる
- 実装: `MainActivity` の `dispatchKeyEvent` で `KEYCODE_VOLUME_UP/DOWN` を捕捉し、
  Pigeon（FlutterApi）でDart側へ通知。**撮影画面がアクティブな間だけ捕捉を有効化**する
  Host API（enable/disable）を用意し、**それ以外の画面では一切捕まえない**
  （比較画面などで音量調整が普通に効くこと）
- 捕捉中はシステム音量を変えない（イベントを消費する）
- 長押しやリピート（`repeatCount > 0`）では多重発火しないこと
- これにより**音量キー信号を送るBluetooth自撮りリモコンでも録画開始/停止が動く**
  （実機にリモコンが無ければ、その旨を「実行できなかった項目」に正直に書く。音量キー自体の
  動作確認は必須）

## 4. 実機確認（Pixel 8）

1. モック5画面と実機の見た目を突き合わせる（配置・大きさ・格納の一致。多少の差異は報告）
2. **全画面・全状態でオーバーフローの縞が出ない**（debugビルドで確認。特に: 比較画面の
   透過/分割両モード、シート展開、位置合わせ中、範囲選択、撮影画面。**未同期状態の比較画面**も必ず）
3. 最下部の操作要素がナビバーと重ならない（SafeArea。全画面）
4. 撮影→ギャラリー保存: 録画後に**フォトアプリ側で動画が見える**。設定OFFで保存されない。
   アプリ内で削除してもフォト側は残る
5. 音量キー: 撮影画面で上/下→録画開始、もう一度→停止。**比較画面やライブラリでは
   音量が普通に変わる**。長押しで多重発火しない
6. 比較画面: 大型リモコンでコマ送り往復・再生・ループ・速度（シート経由）が全部動く
7. 位置合わせ: 分割で触った側が動く/透過でBが動く/リセット/完了/再起動後の復元
8. 「?」で説明が出る（比較範囲・比較の両方）
9. 閉じ方の全経路（シート開いたまま戻る・位置合わせ中に戻る・録画中に戻る 等）でクラッシュしない

## 6. 禁止事項

- ❌ `ComparisonController`・フレーム展開・同期計算・永続化データ構造の変更
  （表示層の組み替えとPigeonへの小さな追加のみ。既存メソッドのシグネチャは変えない）
- ❌ 新しい権限の追加（`WRITE_EXTERNAL_STORAGE` を復活させない。API28はギャラリー保存非対応でよい）
- ❌ 撮影画面以外で音量キーを捕捉すること
- ❌ ギャラリー保存の失敗で録画そのものを失敗させること
- ❌ アプリ内削除でギャラリーのコピーを消すこと
- ❌ 許可外パッケージの追加（MediaStoreはネイティブ実装。プラグイン追加は要確認）
- ❌ 最下部要素のSafeArea無視 / 幅制約なしのRow（オーバーフローの再発）
- ❌ モックにない機能・装飾の追加（実装にない機能を「?」の説明文に書くことも含む）
- ❌ 企画設計書の書き換え / `git push` / フォルダ移動 / iOS実装
