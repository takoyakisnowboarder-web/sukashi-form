# Codex実行報告書 — フェーズ4a

実行日: 2026-07-19

## 実装結果

フェーズ4aの比較基盤を実装した。2本のクリップを共通のミリ秒タイムラインで扱い、最近傍フレームによる連動再生、コマ送り、速度変更、ループ、同期基準の設定と永続化を行える。表示はフェーズ4aの範囲に限定し、A/Bを縦に並べる最小構成とした。フェーズ4bの重ね合わせ、分割、透明度、位置合わせ操作は実装していない。

主な実装内容:

- `lib/comparison/comparison_controller.dart`
  - 純Dartの比較コントローラを追加した。
  - 共通時刻 `τ`、A/Bそれぞれの基準時刻、共通区間、最近傍フレーム探索をミリ秒で管理する。
  - 再生・停止、ループ（初期ON）、0.25x／0.5x／1.0x、1コマ進む／戻るを実装した。
  - フレーム時刻の中点で同距離の場合は後側を選ぶ。
  - 1コマ幅はA/Bの公称フレーム間隔の小さい方を用いる。
- `lib/models/comparison_pair.dart`
  - クリップID順に正規化した比較ペア、基準時刻、将来のフェーズ4bで使う変換値を定義した。
- `lib/data/comparison_pair_repository.dart`
  - `comparison_pairs.json` version 1への原子的保存、破損JSON退避、逆順選択での同一ペア復元を実装した。
  - 現在の比較範囲外に基準時刻が出た場合は設定を無効化し、そのペアを削除する。
  - クリップ削除時は、そのクリップを含む比較ペアも削除する。
- `lib/screens/compare_screen.dart`
  - A/Bの逐次フレーム抽出と `1/2本目`／`2/2本目` の進捗表示を実装した。
  - A/B縦並び、共通シーク、再生操作、フレーム番号、同期基準設定の2ステップ操作を実装した。
  - 10秒超かつ範囲未設定のクリップは拒否し、既存の比較範囲選択画面へ誘導する。
  - 表示中フレームの次を各クリップ最大6枚だけ先読みする。
  - 抽出中、再生中、同期設定中の画面終了を安全に処理する。
- 旧 `compare_stub_screen.dart` を実画面へ置き換え、ルーターを更新した。

## Pixel 8実機確認

端末: Pixel 8 / Android 16 / API 36 / 端末ID `3C041FDJH0038Z`

アプリ自身で5秒×2本、10秒、30秒の4本を撮影して確認した。5秒ペアは実尺4692ms／4859ms、抽出枚数141枚／146枚、検出FPS 30.0512／30.0473であり、異なるフレーム時刻・枚数の組み合わせになった。

1. 5秒クリップ2本の比較
   - 2本を選択して比較画面へ遷移し、A/Bが縦に表示された。
   - A 141枚、B 146枚の異なる抽出結果を共通タイムラインで連動再生できた。
   - 0.25x、0.5x、1.0xの選択状態と進行を確認した。1.0xで動画長を超えて再生し、ループ後も継続した。
2. 1コマ進む／戻る
   - 開始時 `A: 1/141`、`B: 1/146`。
   - 進む操作後 `A: 2/141`、`B: 2/146`。
   - 戻る操作後 `A: 1/141`、`B: 1/146` へ完全に復帰した。
3. 同期基準の保存と再起動復元
   - Aを82枚目、Bを112枚目として基準を保存し、画面が `同期済み` になった。
   - `comparison_pairs.json` に基準時刻2695.404ms／3679.769msと変換初期値が保存された。
   - アプリを強制終了・再起動後も同じ同期設定が復元された。
4. A/B逆順選択
   - 同じ2本を逆順で選択すると `A: 112/146`、`B: 82/141`、`同期済み` となった。
   - ペア設定は選択順ではなくクリップIDへ正しく対応した。
5. 5秒／10秒の異尺比較
   - 10秒側291枚、5秒側146枚を比較し、共通区間終端100%で `A: 147/291`、`B: 146/146` となった。
   - 短い側の終端を越えず、シーク端でもクラッシュしなかった。
6. 10秒超クリップの拒否と範囲指定
   - 29.6秒クリップを範囲未設定で選ぶと「このクリップは10秒を超えています。比較範囲を選択してください。」が表示された。
   - 範囲選択画面で0〜6206msへ設定後、自動的に比較処理へ戻り、A 187枚／B 146枚で比較できた。
7. 範囲変更による同期設定無効化
   - 長尺＋5秒ペアを基準0msで保存後、長尺側の開始を2302msへ変更した。
   - 再度開くと `先頭を基準に同期` へ戻り、該当ペアは `comparison_pairs.json` から削除された。
8. 途中終了の安全性
   - 抽出開始350ms後、連動再生中、同期基準設定ステップ1の途中、の3経路で戻る操作を実施した。
   - すべてライブラリへ復帰し、`FATAL EXCEPTION`、`FlutterError`、接続断はなかった。
   - 抽出キャンセル時は対象キャッシュディレクトリが再作成されず、処理停止を確認した。
9. 再生中メモリ
   - 1.0x連動再生中に8回 `dumpsys meminfo` を採取した。
   - 最大 TOTAL PSS: 839,801KB、最大 TOTAL RSS: 964,172KB、最大 TOTAL SWAP PSS: 1,434KB。
   - 測定中のOOM、アプリ強制終了、フレーム表示停止はなかった。
