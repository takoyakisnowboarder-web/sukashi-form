## 1. 背景（なぜやるか）

比較画面（フェーズ4）は、**2本の映像を画像として重ねる／並べる**。
そのために各クリップを**事前に全フレームのJPEG画像へ展開してキャッシュ**しておく必要がある。

設計書「2.1」の通り、動画プレイヤーを2つ重ねて再生する方式は**採用しない**
（コマ送りのフレーム精度が端末依存でブレ、2本の同期も保証されないため）。
読み込んだ時点でフレーム画像に展開してしまえば、以降は単なる画像の重ね合わせになり、
コマ送りもスライダーも完全に正確かつ滑らかになる。**この展開処理が本フェーズの成果物。**

本フェーズでは「展開してキャッシュする」ところまでを作る。**重ねて表示するのはフェーズ4。**
本フェーズの動作確認は、**開発用の確認画面**（クリップを選ぶと展開が走り、進捗が出て、
展開後のフレーム枚数と最初/中間/最後のフレーム画像が表示される程度のもの）で行う。

### 2.2 Pigeonインターフェースの拡張

`pigeons/frame_extractor.dart` に、フェーズ3aで予告した `extractFrames` を追加する。

想定する形（詳細は任せるが、この意図を満たすこと）:

```dart
class ExtractRequest {
  String absoluteVideoPath;
  String absoluteOutputDir;   // フレームJPEGを書き出すディレクトリ
  int maxLongEdgePx;          // 長辺の上限（既定1280）
  int maxFrames;              // 上限フレーム数（既定600）
  int jpegQuality;            // 既定 85 程度
}

class ExtractResult {
  bool isComplete;            // 上限で打ち切ったら false
  int frameCount;             // 実際に展開できた枚数
  int sourceDurationMs;
  double sourceFps;           // 分かれば。不明なら 0
  String? errorReason;
}

// 進捗を返すため、@FlutterApi でコールバックを受けるか、
// もしくは EventChannel を使う。方式は下記2.4を参照。
```

- **`generateThumbnail` / `probe` の既存シグネチャは変えないこと**（3aで検証済み・動作中）
- 生成物（Dart/Kotlin/Swift）を**再生成してコミットし直す**
- **再生成したことを `docs/06_Pigeon生成手順.md` に追記**するか、変更なしならその旨を報告に書く

### 2.3 Android実装（Kotlin）— ここが本体

`MediaMetadataRetriever#getFramesAtIndex` を使う（**API28以上が必要。minSdk28なので可**）。

- **必ず `try/finally`（または `use`）で `release()` すること**（3aと同じ規律）
- **メインスレッドで展開しないこと。** 数秒の動画でも展開に数十秒かかる。
  バックグラウンドで実行し、進捗をメインスレッドへ返す
- **フレームは一気に全部メモリに載せないこと。** これが最重要。
  - `getFramesAtIndex` はまとめて `List<Bitmap>` を返せるが、**600枚のBitmapを同時に持つと
    確実にOOM（メモリ不足）で落ちる**（1280pxのBitmapは1枚あたり数MB）
  - **小さなバッチ（例: 8〜16枚ずつ）で取り出し、都度JPEGにエンコードしてファイルへ書き、
    Bitmapは `recycle()` して次のバッチへ進む**こと。同時に生きるBitmapを最小に保つ
- **フレームの選び方（サンプリング）:**
  - 動画のfpsやフレーム総数は端末・コーデックで異なる。**元動画の総フレームを機械的に全部
    取ろうとしない**。時間軸で**均等サンプリング**する（例: `durationMs` を対象に、
    `maxFrames` と実fpsから間隔を決めて `getFrameAtIndex` する）
  - **上限は `maxFrames`（既定600） / 10秒相当。** どちらか小さい方で打ち切り、
    `isComplete=false` を返す。10秒を超えるクリップはトリミング（3.5）で対応する前提
- **出力:** 連番のJPEG（`frame_000000.jpg`, `frame_000001.jpg`, …）。長辺 `maxLongEdgePx`、
  品質 `jpegQuality`。**アトミックに（一時ファイル→rename）書くこと**
- **回転（rotation）を正しく適用すること。** 縦持ち撮影の動画はメタデータに回転情報を持つ。
  展開したJPEGが横倒しにならないよう、`METADATA_KEY_VIDEO_ROTATION` を反映する

### 2.4 進捗の返し方

展開は数十秒かかる。**無言のスピナーは不可**（ユーザーは固まったと思う）。

- 「N / 総数 フレーム」または「◯%」が更新される形にすること
- 実装方式は任せるが、以下のいずれか:
  - Pigeon `@FlutterApi` のコールバックで進捗イベントを push する
  - `EventChannel` で進捗ストリームを流す
- **UI層はサービス層経由でのみ進捗を受け取ること**（Pigeon/EventChannelを直接触らない）
- **キャンセルできること。** 展開中に確認画面を閉じたら、バックグラウンドの展開を止める
  （少なくとも、破棄されたUIに向けて結果を返そうとしてクラッシュしないこと）

### 2.5 キャッシュ管理（Dart側サービス）

展開結果は大きい（3秒×60fps≒27MB/本）。**管理を誤るとストレージを食い潰す。**

- 保存先: アプリ専用ディレクトリの `frames/<clipId>/frame_000000.jpg …`
- **既に展開済みのクリップは再展開しない。** `frames/<clipId>/` に完全なセットがあれば
  それを使う（「完全」の判定方法も実装すること。例: 期待枚数のマニフェストを1つ置く）
- **クリップ削除時に `frames/<clipId>/` も削除すること**（既存の削除導線に追加）。
  動画・サムネイル・フレームキャッシュの3つが揃って消えること
- **破損クリップ（`isBroken==true`）は展開しない**（3aで検出済み。展開しようとして失敗させない）
- キャッシュ全体の破棄（`deleteCache`）も用意してよい（Pigeonに定義済みなら実装、無ければDartで
  `frames/` を消す関数でよい）
- **`ClipRepository` / `SettingsRepository` と同じ規律**（相対パス、アトミック、リポジトリクラスに
  閉じ込め、UIから直接ファイルI/Oを触らせない）を踏襲すること

### 2.6 開発用の確認画面

本フェーズの成果を実機で確認するための最小画面。**凝らなくてよい。**

- ライブラリからクリップを1本選び、「フレーム展開（開発用）」で展開を起動できる
  - 導線は目立たない形でよい（デバッグメニュー、長押しメニューの一項目など）。
    **本番UIに残さないこと**（`kDebugMode` で囲う等）
- 展開中に**進捗（N/総数 or %）が動く**こと
- 展開後に「◯枚展開しました」と、**最初・中間・最後のフレーム画像**を表示する
  （回転が正しいか、実際に画像が出るかを目視するため）
- 再度同じクリップを選んだら、**再展開せずキャッシュから即座に出る**こと（2.5の確認）

> **注意:** これは開発用であり、比較機能（重ね表示・透過・分割）ではない。

## 4. 実行と確認

**必ず実機で確認すること。**

- 実機: **Pixel 8 (Android 16 / API 36)** をUSB接続
- デバッグAPK:
  ```
  flutter build apk --debug
  adb install -r build\app\outputs\flutter-apk\app-debug.apk
  ```
- **確認すべき実機シナリオ（報告に結果を書くこと）:**
  1. 数秒のクリップを撮影 → 開発用画面で展開 → 進捗が動き、フレーム画像が表示される
  2. **縦持ちで撮った動画のフレームが横倒しにならない**（回転が正しい）
  3. 同じクリップを再度展開 → **キャッシュから即座に出る**（再展開しない）
  4. **20〜30秒の長いクリップ**（フェーズ2で録画時間30秒が可能）を展開 → 
     **OOMで落ちず**、上限（600枚/10秒相当）で `isComplete=false` になる
  5. 展開後にクリップを削除 → `frames/<clipId>/` が消える
  6. 破損クリップ（0バイト動画）を展開しようとしても、クラッシュせず弾かれる
- **メモリの実測を必ず行うこと:**
  ```
  adb shell dumpsys meminfo com.sukashiform.app
  ```
  展開中のピークメモリを確認し、報告に記載する。**OOMで落ちないことが最重要。**
