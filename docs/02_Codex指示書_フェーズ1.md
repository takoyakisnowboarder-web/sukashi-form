## 1. 背景（なぜやるか）

スカシフォームは、スポーツの一瞬の動作（ゴルフ/野球のスイング、スノーボードのキッカーなど、
数秒のクリップ）を2本撮って**半透明で重ねて比較**するFlutterアプリ。買い切り500円、サーバーなし。

このフェーズ1は、後続フェーズ（撮影・フレーム展開・比較画面）が乗る**土台**を作る。
ここでデータの持ち方と画面遷移を固めておかないと、フェーズ4の比較画面で必ず手戻りが出る。

フェーズ1の時点では**動画は扱わない**。クリップはダミーデータで表現し、
一覧表示・削除・メモ編集・2本選択までが動けばよい。

## 2. 具体的な作業内容

### 2.1 プロジェクト雛形

- Flutter（stable系）、Dart 3系で新規作成。
- プロジェクト名: `sukashi_form`
- applicationId: `com.sukashiform.app`
  → **これはストア公開後に変更不可。** 変更したい場合は着手前にユーザーへ確認すること。
- **`minSdkVersion` を 28 に設定する。**
  理由: フェーズ3で使う `MediaMetadataRetriever#getFramesAtIndex` が API 28 以上を要求するため。
  今のうちに設定しておかないと、フェーズ3で気付いて手戻りになる。
- iOSディレクトリは生成されたままでよいが、**iOS向けの設定変更・実装は行わない**。

### 2.2 依存パッケージ（許可リスト）

以下**のみ**を使うこと。これ以外の追加は理由を添えてユーザーに確認する。

| パッケージ | 用途 |
|---|---|
| `flutter_riverpod` | 状態管理 |
| `go_router` | ルーティング |
| `path_provider` | アプリ専用ディレクトリの取得 |
| `uuid` | クリップID採番 |
| `intl` | 日時表示のフォーマット |

**禁止:**
- `ffmpeg_kit_flutter` 系（2025年に開発終了・バイナリ配布停止済み。絶対に入れない）
- `build_runner` / `freezed` / `json_serializable` などのコード生成系
  → モデルが小さいため **`toJson` / `fromJson` は手書きする**。ビルドの複雑化を避ける。
- 状態管理を Riverpod 以外と混在させること（Provider/Bloc/GetX等）
- アナリティクス・広告・クラッシュレポートのSDK（本アプリは通信を一切行わない）

### 2.3 データモデル

```dart
class Clip {
  final String id;            // uuid v4
  final String videoPath;     // アプリ専用ディレクトリ内の「相対」パス
  final String? thumbnailPath;// 同上。フェーズ1ではnull可
  final DateTime recordedAt;  // 撮影日時
  final int durationMs;       // 長さ(ミリ秒)
  final String? memo;         // ユーザーの一言メモ（例「ドライバー 調子○」）
}
```

**重要: パスは必ず相対パスで保存すること。**
iOS/Androidともにアプリのサンドボックスの絶対パスはOSアップデートや再インストールで
変わり得るため、絶対パスを保存すると次回起動時にファイルを見失う。
読み書き時に `path_provider` で得たベースディレクトリと結合して絶対パスにする。

### 2.4 永続化

- 保存先: `getApplicationDocumentsDirectory()` 配下の `clips.json`
- 件数が少ないためDBは使わない。JSONファイルで十分。
- **書き込みは必ずアトミックに行う**（一時ファイルに書いてから rename）。
  撮影直後にアプリが落ちて `clips.json` が壊れ、全クリップを失う事故を防ぐため。
- **JSONが壊れていた／存在しなかった場合はクラッシュさせず、空リストとして起動する。**
  壊れたファイルは `clips.json.broken` にリネームして残す（原因調査のため、黙って消さない）。
- `ClipRepository` クラスに閉じ込める。UI層からファイルI/Oを直接触らせない。
  （フェーズ3以降で保存方式が変わってもUIに影響させないため）

### 2.5 状態管理

- `clipRepositoryProvider` … リポジトリのDI
- `clipListProvider` … `AsyncNotifier<List<Clip>>`。一覧の読み込み・追加・削除・更新
- 選択状態（比較する2本）は別プロバイダに分ける。永続化しない。

### 2.6 ルーティング（go_router）

| パス | 画面 | フェーズ1での状態 |
|---|---|---|
| `/` | ライブラリ画面 | **実装する** |
| `/capture` | 撮影画面 | **空のスタブ**（"フェーズ2で実装" とだけ表示） |
| `/compare` | 比較画面 | **空のスタブ**（選択した2件のidを受け取れることだけ確認） |

スタブ画面の中身を作り込まないこと。

### 2.7 ライブラリ画面（今回の実装対象）

- クリップ一覧を **GridView** でサムネイル表示
  - フェーズ1では実サムネイルがないため、プレースホルダ（グレーの矩形＋アイコン）でよい
  - 各セルに: 撮影日時 / 長さ / メモ（あれば）
- **タップで選択。最大2本まで。** 3本目を選ぼうとした場合は無視するか、
  最初の1本の選択を外す（どちらか一貫した挙動にし、報告に書くこと）
- 2本選択されたときのみ「比較する」ボタンを有効化 → `/compare` へ遷移
- **長押しでメニュー**: 削除 / メモ編集
  - 削除は確認ダイアログを出す（誤タップ防止）
  - 削除時は**動画ファイル本体とサムネイルも削除する**（フェーズ1ではダミーのため実ファイルなし。
    ただし削除処理の口はリポジトリに用意しておくこと）
- クリップが0件のときは空状態を表示（「まだクリップがありません」＋撮影を促す文言）
- 右下にFAB: 「撮影」（→ `/capture`）
  - 「端末の動画から取り込み」もv1必須機能だが、**フェーズ2で実装する。今回は置かない。**

### 2.8 ダミーデータ

デバッグ用に、ダミークリップを数件投入する手段を用意する（デバッグメニュー or 初回起動時のシード）。
**本番ビルドに残さないこと**（`kDebugMode` で囲うなど）。
