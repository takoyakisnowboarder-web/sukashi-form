# Androidリリース署名手順

この作業はアプリのオーナー本人が行います。Codexは署名鍵を生成せず、パスワードも決めません。

## 最重要の警告

署名鍵とそのパスワードを失うと、同じ`applicationId`（`com.sukashiform.app`）のアプリを更新できなくなる可能性があります。Google Play App Signingを利用する場合も、通常の更新で使うアップロード鍵の管理は必要です。

次のファイルはGitへコミットしないでください。プロジェクトの`.gitignore`で除外済みです。

- `android/key.properties`
- `*.jks`
- `*.keystore`

## 1. アップロード鍵を生成する

PowerShellで次の例を参考に実行します。保存先、エイリアス、パスワードはオーナー自身が決めてください。実際のパスワードをコマンド履歴、ソース、文書、チャットへ残さないでください。

```powershell
keytool -genkeypair -v `
  -keystore <安全な保存先>\sukashi-form-upload.jks `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -alias <オーナーが決めたエイリアス>
```

対話中にキーストアと鍵のパスワードを入力します。パスワードは伏せ字のまま、この文書へ記録しないでください。

## 2. `android/key.properties`を作る

`android/key.properties`を新規作成し、次の4項目を記入します。`storeFile`は`android`フォルダから見た相対パス、または絶対パスを指定できます。

```properties
storeFile=<署名鍵へのパス。例は記入せず実値を本人が設定>
storePassword=<キーストアのパスワード>
keyAlias=<鍵のエイリアス>
keyPassword=<鍵のパスワード>
```

作成後、次を確認します。

```powershell
git check-ignore -v android/key.properties
git status --short
```

`android/key.properties`と鍵ファイルが`git status`へ出ないことを確認してください。

## 3. AABを作る

プロジェクト直下で実行します。

```powershell
flutter clean
flutter pub get
flutter build appbundle --release
```

生成物は通常`build/app/outputs/bundle/release/app-release.aab`です。鍵情報がなければ、ビルドは分かりやすいエラーで停止します。debug鍵への自動フォールバックはしません。

## 4. バックアップ

最低でも次を別々の安全な場所へ2系統保存してください。

1. `.jks`または`.keystore`本体
2. エイリアス、キーストアパスワード、鍵パスワードを記録したパスワードマネージャー項目

推奨例:

- 暗号化された外付け媒体
- 信頼できるクラウドストレージの暗号化保管庫
- パスワードマネージャーの安全なメモ

鍵本体と復旧情報を同じ1台のPCだけに置かないでください。バックアップから読み出せることも一度確認します。

## 5. Google Play App Signing

Google Play ConsoleではGoogle Play App Signingの利用を推奨します。

- Googleが配信用のアプリ署名鍵を管理する
- オーナーはアップロード鍵でAABを署名して提出する
- アップロード鍵を紛失した場合は所定のリセット申請が可能だが、本人確認と手続きが必要

この仕組みを使ってもアップロード鍵の安全なバックアップは必要です。Play Consoleへの登録、規約同意、鍵の選択、提出操作はオーナー本人が行います。
